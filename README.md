# 콜명함 — 통화 후 명함·소개글 발송 앱

전화를 받거나 놓친 뒤, 상대방에게 **명함 이미지 + 소개글을 MMS로** 보내는 앱입니다.
직원이 각자 자기 휴대폰에 설치하고, 자기 명함과 소개글을 설정해서 씁니다.

| | Android | iPhone |
|---|---|---|
| 통화 종료·부재중 자동 감지 | ✅ | ❌ (iOS가 앱에 통화 번호를 알려주지 않음) |
| 발송 방식 | **자동 발송** / **발송 전 확인 알림** 중 선택 | 반자동: 번호 붙여넣기 → [명함 보내기] → 메시지 앱에서 [전송] |
| 부재중 전화용 문구 따로 설정 | ✅ (비워두면 기본 문구) | ✅ (보낼 때 '부재중' 선택) |
| 예시 문구 자동 생성 | ✅ (회사명·이름·연락처 입력 → 정중/친근/간결) | – |
| 같은 번호 하루 1회 | ✅ 자동 적용 | ✅ (다시 보낼지 확인) |
| 휴대폰 번호(010 등)에만 발송 | ✅ 옵션 | – |
| 배포 | APK 직접 설치(사내 배포) | Apple 개발자 계정 필요(TestFlight 등) |

## 🚀 배포·업데이트 (GitHub)

- `android/` 코드를 고쳐 `main`에 올리면 **GitHub Actions가 APK를 빌드해서 [Releases]에 올립니다.** (`.github/workflows/release-android.yml`)
- 직원은 **Releases의 최신 `callcard-v1.xx.apk`** 를 휴대폰에서 받아 설치합니다(처음 한 번).
- 이후에는 앱이 **하루 한 번 새 버전을 확인해 알림**을 띄우고, 앱 상단 **[업데이트 확인]** 으로도 확인할 수 있습니다. [업데이트] → 다운로드 → 설치 화면에서 **[설치]** 한 번만 누르면 됩니다.
  - 스토어 밖 앱은 Android 정책상 사용자가 마지막 [설치]를 직접 눌러야 합니다(완전 무음 업데이트 불가).
  - 처음 업데이트할 때 '이 출처의 앱 설치 허용'을 한 번 켜야 합니다.
- 서명 키는 저장소 **Secrets**에만 보관합니다(`CALLCARD_KEYSTORE_B64`, `CALLCARD_KEYSTORE_PASSWORD`, `CALLCARD_KEY_ALIAS`, `CALLCARD_KEY_PASSWORD`). 키 파일은 절대 코드에 올리지 마세요.
- Android Studio에서 직접 빌드한 APK(디버그 키)와 Releases의 APK는 서명이 달라 **서로 업데이트되지 않습니다.** 직접 빌드본을 쓰던 폰은 한 번 삭제 후 Releases 버전을 설치하세요.

## Android (`android/`)

### 동작 흐름
1. 전화 상태가 '대기'로 돌아오면(통화 종료 또는 부재중) 4초 뒤 통화 기록을 확인합니다.
2. 가장 최근 통화가 **받은 전화** 또는 **부재중 전화**이고, 설정에서 켜 둔 유형이면 다음 단계로 갑니다. 건 전화·거절·차단 통화는 보내지 않습니다.
3. 휴대폰 번호인지, 오늘 이미 보낸 번호인지 확인합니다.
4. **자동 발송**이면 바로 MMS를 보내고, **확인 모드**이면 알림의 [보내기]/[안 보내기] 버튼으로 결정합니다.
5. 실패하면 알림을 띄웁니다. 실패한 번호는 '하루 1회' 기록에서 빠지므로 다음 통화 때 다시 보낼 수 있습니다.

### 빌드
Android Studio(최신)에서 `android/` 폴더를 열고 **Build › Build APK(s)**를 누르세요. 명령줄로는:
```bash
cd android && ./gradlew assembleRelease
```
결과물은 `android/app/build/outputs/apk/release/app-release.apk`입니다.
> 지금은 디버그 키로 서명됩니다. 사내 배포 전에 회사 키스토어로 바꾸는 것을 권장합니다(`app/build.gradle.kts`의 `signingConfig`).

### 설치·첫 설정 (직원용)
1. APK를 설치합니다. '출처를 알 수 없는 앱' 설치를 허용해야 합니다.
2. 앱에서 **[권한 허용]**을 누르고 전화, 통화 기록, SMS, 알림 권한을 모두 허용합니다.
   - 허용 버튼이 회색으로 막혀 있으면 **설정 › 애플리케이션 › 콜명함 › 우측 상단 ⋮ › '제한된 설정 허용'**을 누른 뒤 다시 시도하세요. 직접 설치한 APK에 Android 13 이상이 거는 제한입니다.
3. **[배터리 최적화 제외]**를 누릅니다. 삼성 등 일부 기기는 앱을 절전 상태로 두면 통화 감지가 늦거나 빠질 수 있습니다.
4. 명함 이미지, 제목, 소개글, 부재중 전화용 소개글(선택), 발송 조건, 발송 방식을 정하고 **[저장]**합니다.
5. **테스트 발송**으로 내 번호(또는 동료 번호)에 보내 실제 수신을 확인합니다.
6. **[명함 발송 사용]** 스위치를 켭니다.

### 알아둘 점
- **구글 플레이 스토어에는 올리기 어렵습니다.** 통화 기록·SMS 권한은 기본 전화·문자 앱 등 예외 용도에만 허용됩니다(Google Play "SMS 및 통화 기록 권한" 정책). 그래서 사내 APK 배포를 전제로 만들었습니다.
- MMS 발송 비용은 각자의 휴대폰 요금제에 따릅니다. 문자 무제한 요금제는 보통 MMS도 포함되지만, 요금제마다 다르니 확인하세요.
- 명함 이미지는 MMS 용량에 맞게 약 280KB 이하로 자동으로 줄여 저장합니다.
- 발송 기록과 하루 1회 기록은 **휴대폰 안에만** 저장되고 외부 서버로 전송되지 않습니다. 기록 화면에서는 번호 가운데를 가립니다.
- MMS 데이터는 앱이 직접 만들어(`MmsPdu.kt`) 시스템 MMS 서비스로 보냅니다. 기본 문자 앱이 아니면 보낸 메시지가 문자 앱의 대화 목록에 **남지 않을 수 있습니다.** 보낸 내역은 앱의 '최근 기록'에서 확인하세요.

### 파일 구성
| 파일 | 역할 |
|---|---|
| `CallStateReceiver.kt` | 통화 종료(IDLE) 감지 → 확인 작업 예약 |
| `CallLogWorker.kt` | 최근 통화 기록 판별(받은 전화/부재중), 조건 검사, 발송 또는 알림 |
| `MmsSender.kt` / `MmsPdu.kt` | MMS 데이터 생성과 발송 |
| `MmsSentReceiver.kt` | 통신사 전송 결과 처리 |
| `Notifier.kt` / `ConfirmActionReceiver.kt` | 확인 알림과 [보내기]/[안 보내기] 처리 |
| `Prefs.kt` | 설정, 하루 1회 기록, 발송 기록 |
| `MainActivity.kt` | 설정 화면 |

## iPhone (`ios/CallCard/`)

iOS는 앱이 통화 번호를 읽거나 사용자 확인 없이 문자를 보내는 것을 허용하지 않습니다. 그래서 **반자동**으로 만들었습니다.

**사용 순서:** 통화 종료 → [최근 통화]에서 ⓘ → 번호 길게 눌러 복사 → 콜명함 앱에서 붙여넣기 → **[명함 보내기]** → 명함과 소개글이 채워진 메시지 화면에서 **[전송]**

### 빌드
1. Xcode에서 **File › New › Project › iOS App**(SwiftUI, 최소 iOS 16)으로 `CallCard` 프로젝트를 만듭니다.
2. 자동으로 만들어진 `ContentView.swift`와 `CallCardApp.swift`를 지우고, `ios/CallCard/`의 Swift 파일 4개를 추가합니다.
3. 실기기에서 실행합니다. 시뮬레이터는 문자를 보낼 수 없습니다.
4. 동료에게 배포하려면 Apple Developer Program 계정으로 TestFlight를 쓰거나 Apple Business Manager의 사내 배포를 이용해야 합니다.

## ⚠️ 도입 전 확인 (사람 승인 필요)
- **사내 승인:** 고객에게 자동으로 나가는 메시지이므로, 회사 업무용으로 쓰려면 **조직장 승인**과 소개글 문안 검토가 필요합니다.
- **광고성 정보 규정:** 소개글에 홍보·영업 내용이 들어가면 정보통신망법의 영리목적 광고성 정보 전송 규정(사전 동의, `(광고)` 표기, 야간 발송 제한, 수신거부 방법 안내 등)이 적용될 수 있습니다. 해당 여부는 **법무 담당자에게 확인**하세요. 이 문서는 법적 판단이 아닙니다.
- **개인정보:** 상대방 번호는 발송에만 쓰이고 기기 밖으로 나가지 않습니다. 그래도 사내 개인정보 처리 기준에 맞는지 확인하세요.
- **실기기 테스트:** 이 코드는 컴파일과 MMS 데이터 구조까지만 확인했습니다. 실제 통신사(SKT, KT, LG U+)와 여러 기종(삼성, 픽셀 등)에서 발송이 되는지는 **아직 시험하지 않았습니다.** 배포 전에 꼭 테스트하세요.
